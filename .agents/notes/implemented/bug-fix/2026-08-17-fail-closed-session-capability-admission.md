# Agent Note: Fail-closed session capability admission

Status: implemented

English | [中文](2026-08-17-fail-closed-session-capability-admission.zh.md)

## Problem

An Agent implementation may own text execution while lacking DSH image, model-selection, or seeded-fork behavior. The Host enforced some of those differences, but the native Web conversation initially exposed image intake and branch actions before its capability read settled. A session switch could also render one frame from the previous session's loaded snapshot. Separately, an unknown slash command addressed to a cold persisted session resumed and published its Agent before the Host learned that no handler existed.

These optimistic paths made unavailable controls actionable and let a definite command miss mutate process state before returning an error.

## Decision

`AgentFactory.sessionCapabilities` is an optional factory-wide declaration. Seeded fork admission requires the exact positive declaration `forkFromSeed: true`; false or omission fails closed. The stock AgentLoop declares true because its creation path validates and snapshots a seed. Each `setFactory()` call creates a distinct registry slot, snapshots that declaration, and returns its exact callable effect disposer as an opaque `AgentFactoryRegistration` receipt. The registry's create and resume wrappers carry that slot only until the returned Promise settles. A registered factory that publishes directly must supply the exact receipt to `enter()`; stale receipts from an earlier registration of the same factory object, foreign-registry receipts, and raw factory objects are rejected. Omission never borrows the active factory's declaration, so an external direct registration remains unknown. The stock AgentLoop keeps the receipt outside the traced Service object and captures it at operation entry, before setup or persistence awaits, so declarative exact-`sessionId` creation and `resumeSessionId` restoration retain the correct registration epoch. `enter()` validates that epoch before reading its snapshot and again immediately before committing the live entry. Fork execution has a separate second gate: after the Host establishes source eligibility from the live source's publication snapshot or the cold source's active registration snapshot, `AgentRegistry.create()` captures the execution slot and requires that slot's own `forkFromSeed: true` before invoking its factory. Registration A may therefore admit a source that capable replacement B executes, but false or omitted B fails with `AgentFactoryCapabilityUnavailableError`; the Host maps that typed refusal to the stable `fork-unavailable` wire error. The Host returns `imageInput`, `modelSelection`, and `fork` in ordinary `session.models.capabilities` and enforces the same facts in the corresponding write paths. An authorized addressed `subagent.history` tail carries only `{ fork }`, after catalog and lineage rechecks; it never advertises image or model authority, and older pages omit capabilities.

The runtime Session owns one ordinary `SessionModels` authority exposed as the read-only `modelDirectory` observable. `ConversationSnapshot.sessionCapabilities` derives from that same value, and the stock model-selection plugin delegates load, owner-event refresh, and selection to the Session instead of keeping a second groups/current/routable projection or issuing its own RPC. Every consumer therefore joins or reuses one settled read for the ready generation. Disconnect, generation start, explicit refresh invalidation, and a switch to addressed subagent transport synchronously retract the authority, invalidate reads and selections, and fence late settlements by request identity, connection generation, answerable generation, and ordinary-session address. Pending, business-error, transport-failure, and stale responses all remain unavailable. Addressed history installs its fork-only fact in the separate `ConversationSnapshot.forkAvailable` field; address, disconnect, and generation epochs retract and fence it independently, so it cannot become image or model authority. Owner events invoke the model-selection plugin's private closure, which enumerates the public sessions list and calls `refreshModels` through each binding; each refresh retracts first and starts one replacement read, and live facades join it. The composer model entry receives `useSession` and `useDirectory` through the framework's derived props shares, so ordinary/addressed transitions converge without a provide-bundle rebuild or component-owned subscription machinery. InputBar and ChatView use that same Session selector; image paste and drop preserve the draft and attachment rail while unavailable, and transcript branch actions are absent.

The command registry exposes `has(name)` as a read-only, Agent-free coarse index over every global and scoped registration. A false result proves a definite miss. `session.prompt` rejects that miss as `unknown-command` before Agent lookup, so a cold session remains cold and records no event. A true result permits Agent resolution but grants no scoped availability: the existing `find(agent, name)` remains authoritative after resume, and execution still records the stock `command/run` and `command/done` pair. Neither admission path contains provider, Agent implementation, or command-name exceptions.

## Verification

Runtime tests require pending and failed generations to remain unavailable, disconnect, generation start, and refresh invalidation to clear synchronously, repeated consumers to share one read, addressed children to issue no ordinary model RPC, and late reads or selections to be discarded across generation/address changes. Two subscribers observe the same Session authority while the API records exactly one `session.models` call. Client tests require the stock model entries to subscribe to that same source, private owner-event refresh to reach Sessions with never-materialized or disposed facades, and one mounted composer control to hide and restore across ordinary/addressed transitions. The keyless Web replay also drives an ordinary parent to an addressed child and back through the real Loader, app, browser, and profile composition while asserting that control transition. Supported session A to unavailable or declined session B transitions preserve image draft/rail state and expose no branch action. The artifact gate builds the package, runs a real `pnpm pack` into an absolute temp destination, lists the tarball through `tarballFiles`, and compares all 77 official members literally, including 69 declaration files and the three runtime JavaScript files; a required workflow lane invokes that exact artifact graph. The generated Cordis inspect catalog records the optional `ConversationSnapshot.forkAvailable` field, keeping runtime introspection aligned with the exported client declaration.

Registry tests require direct external publication to remain undeclared while a capable factory is active. They also cover deferred create and resume from registration A after A is disposed and registration B takes over, detached async-local descendants after the invoking Promise settles, stale A receipts after the same factory object is registered again as B, raw factory objects, foreign-registry receipts, traced Cordis factory publication, and reentrant replacement during registration or publication. Every stale path must fail before registry mutation, while the exact current receipt succeeds with the same session id. The seeded-create matrix requires false and omitted execution slots to reject before factory invocation and a true slot to receive the seed. A public Host race stalls cold source inspection after A(true) source admission, replaces A with B(false or omitted), then requires the stable `fork-unavailable` result, zero B factory calls, and unchanged Agent and Session registries; the symmetric A(true)-to-B(true) case requires B to execute and publish the child. A keyless shipped-Web composition creates an exact configured Agent, forks it through public Host HTTP, restarts over the same persistence root through `resumeSessionId`, verifies the materialized history, and forks the restored Agent through the same public operation. Public Host tests cover addressed capability reads across live and cold children, one-shot and continuable modes, and true, false, and omitted factory declarations. They require only the authorized tail page to consult the non-activating registry declaration, errors and older pages to skip the lookup, and direct fork admission to accept only the same exact true declaration. Client tests retract addressed fork authority on disconnect and generation start, reject late old-address and old-generation settlements, restore it from a ready generation, and issue no `session.models` request. Separate Host tests address an unknown command to a persisted cold session and require the stable `unknown-command` response, zero factory resume calls, no live Agent or Session, and an unchanged public session list. A registered command may resume and must retain the command lifecycle pair. Registry tests hold the same command name in global and independent scoped layers and dispose them one at a time, proving that the coarse index remains true until the final registration leaves.

## Alternatives considered

**Expose controls optimistically and rely on Host rejection.** The Host remains authoritative, but an enabled control promises an operation the current session may not implement. It also lets paste or drop disturb local draft state before the rejection arrives.

**Reset capability state only in a passive effect.** Effects run after render, so a session or connection switch can commit UI from the previous key. Capability state belongs in the Session generation lifecycle and must clear before the new generation can render.

**Resume every cold session before checking a slash name.** Exact scoped resolution does require an Agent, but a name absent from every registration is already a definite miss. Resuming it creates process state that the rejected command never needed.

**Treat the active factory, or its raw canonical object, as the publisher of every directly registered Agent.** An external Agent can enter the registry while an unrelated capable factory is active, and one factory object can be disposed and registered again in a new epoch. Falling back to the active slot would turn an unknown implementation into a positive seeded-fork declaration; comparing the raw object would let an old operation publish under its replacement registration. Both violate fail-closed admission, so direct publication must prove the exact per-registration receipt instead.

**Hardcode unsupported providers or command names in the Host.** Such branches would couple generic DSH admission to one deployment and drift as Agent implementations and command plugins change.

## Consequences

Native controls fail closed across loading, transport failure, Session replacement, and connection-generation changes, while supported sessions regain the same stock controls after their current-generation read succeeds. Business state remains in the resident Session object layer, `contract/` stays declaration-only, and the packed package retains its exact official inventory. A factory must explicitly declare seeded-fork support and retain the exact receipt returned by `setFactory()` when publishing outside the registry's create or resume wrappers. Because Cordis may wrap a function stored on a traced Service field, the receipt belongs in a closure, module-private `WeakMap`, or other plain holder rather than such a field. The stock AgentLoop follows that rule for declarative create and restore, while an undeclared external Agent remains unavailable.

Unknown slash names cannot wake cold sessions. Because `has(name)` is intentionally coarse, a name registered only for another scope may still cause a resume before exact `find()` rejects it; the index prevents definite misses from resuming but does not replace scoped resolution or advertise availability to clients.
