# Agent Note: Workspace 目录就绪状态

Status: implemented

[English](2026-09-02-workspace-catalog-readiness.md) | 中文

## Problem

Workspace 浏览器会组合各自独立获取的 Session 与 Workspace 列表。在任一部分响应到达后就进行渲染，会让短暂的子集看起来像完整结果，使操作作用于不完整的成员关系，也会让依赖目录的诊断检查仍在变化的状态。

## Decision

运行时的标准 Session 快照以可选的增量字段暴露既有的拉取活动与错误，官方运行时始终发布这些字段。这些字段保持可选，使现有插件测试替身和兼容的运行时实现无需立刻修改源码。

`WorkspaceBrowser` 直接从 Session 与 Workspace 快照派生唯一的目录就绪值。在 `baselinesReady` 为真之前，它隐藏目录树和目录操作；后续刷新期间保留最近一次完整目录树，并以稳定的重试文案呈现状态而不暴露原始传输错误。重试调用两个既有运行时刷新方法；Host 实现继续负责请求合并。

这是基于既有对象层事实的展示协调，不会创建第二个目录 store 或独立的就绪状态权威。

## Alternatives considered

**每个列表到达后立即渲染。** 未采用，因为浏览器把两个列表呈现为同一个目录，无法把部分成员关系标作完整结果。

**把目录数据复制到浏览器自有 store。** 未采用，因为这会产生竞争状态、同步规则和陈旧数据失败模式；现有运行时快照已经持有全部必要事实。

**立刻将 Session 增量字段与刷新方法设为必填。** 未采用，因为这会破坏其他方面仍兼容的插件实现与测试替身。官方运行时提供这些数据，而可选的对外声明保留源码兼容性。

## Consequences

- 首次启动只有一个明确的加载或重试边界，不再显示持续变化的不完整目录树。
- 后台刷新会保留最近一次完整目录，并在结果陈旧时明确标注。
- 目录操作不会作用于首次加载中的不完整成员关系投影。
- 兼容的第三方实现可以省略增量字段；浏览器会依据既有到达阶段保守派生状态。

## Testing

Workspace 浏览器组件测试覆盖首次加载、首次失败与重试、完整目录树刷新以及旧结果呈现。客户端类型检查验证增量运行时与 slot 接口。
