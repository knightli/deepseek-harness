# @deepseek-ai/dsh-client-ui-model-selection

English | [中文](README.zh.md)

Model selection plugin, browser half: TWO entries over ONE runtime Session-owned directory. `ModelDirectoryResolver` (`ctx.modelDirectories`) creates only a thin facade for each session: the `/model` popupSelect contribution (registered through `ctx.commandUi`) and the composer's named `conversation.input.model` seat subscribe to the same `Session.modelDirectory` observable and delegate `loadModels`/`refreshModels`/`selectModel` to that Session. The plugin keeps no second groups/current/routable store and issues no wire RPC. A directory whose external authority does not yet know the exact next-step selection has `current: null`: both entries still list every advertised model, show no active row, and the composer keeps `Select model` until the Session authority publishes an exact selection. A product-specific composer block may keep that trigger inert while the Session awaits explicit activation. The compact composer trigger otherwise opens a two-level Model/Effort menu: models stay provider-grouped, while the selected exact model supplies its adapter-owned effort names, descriptions, and default. `/model` applies the selected model's default effort, and the composer can then choose any advertised effort.

The Host-reported provider/model/reasoning `ModelSelection` is the single selection fact, but it is echoed only when the exact provider/model pair remains in the advertised groups; an absent catalog row leaves the routable selection intact while the trigger prompts `Select model`, no stale row is synthesized, and no Effort row is shown until the user picks an advertised model. Runtime request identity and connection generation prevent an older response from overwriting a newer one; disconnect retracts the directory synchronously and reconnect reloads the Host-restored selection before display. Provider-local metadata failures list inline while usable groups stay selectable, and selection failures retain the prior selection and directory.

When the Host reports `session.models.routable: false`, this plugin raises a composer block through `ctx.conversation.blocks` and the input goes inert with this plugin's own copy; recovering clears it without a reload. The value follows Host admission for ordinary text, not adapter presence alone: it is true when a DSH adapter serves the selected provider or the live Agent declares `promptExecution: { kind: 'external-text' }`. The plugin follows `routable` and nothing else: a `null` — before the first load, or after one failed — never blocks, or a slow Host would lock a working composer, and catalog membership never blocks either. For an `external-text` Agent the directory is compatibility display only; `session.selectModel` returns `model-unavailable`, and the directory retains its prior selection and groups. The trigger's own `Select model` fallback remains display, not prompt admission ([decision](../../../.agents/notes/implemented/architecture/2026-08-14-external-text-prompt-execution.md)).

Facades are resolved lazily through `ctx.modelDirectories.directoryFor(sessionId)` and disposed with the session scope; the underlying authority remains on the resident runtime Session. The composer entry derives visibility from the framework's standing `useSession` share and reads the directory through the inject `hooks` share, so it owns no subscription machinery and ordinary/addressed transitions converge without recreating the identity-stable provide bundle. Addressed subagent sessions expose neither entry, and the Session rejects loads, selections, and reconnect refreshes without issuing an ordinary Agent-bound model RPC, because that transport would activate persisted child history outside the direct-parent continuation path.

Forwarded `llm/adapters-updated` and `settings/document-updated` owner events call a private capability closure owned by this plugin. The closure enumerates the public sessions list, resolves each binding, and calls its Session's `refreshModels`; every refresh synchronously retracts stale facts and starts one replacement read, while live facades join the same in-flight request. Provider topology, provider catalogs, and the default selection therefore converge without a parallel UI Session registry, a one-consumer public runtime method, or a separate model-change alias.

The `/client` exports are the plugin body (`apply`/`inject`), `ModelDirectoryResolver`, `ModelDirectory` with its state fields, and the seat's injected face type.

## Model Experience

Indirectly, through the `session.selectModel` RPC available to ordinary sessions, both entries submit the complete `ModelSelection` that the Host snapshots at the next prompt-assembly boundary, so the following request uses the selected provider, model, and effort while a running step keeps its assembled selection; the selection becomes durable only when the existing request header records a request that consumes it, and menu interaction adds no prompt content.

#### KV Cache effect

Switching the route can reduce or invalidate provider-side cache reuse for subsequent requests; the prompt prefix itself is untouched.

## Known Limitations and Deferred Work

- **No create-time or addressed-subagent selection** — both entries require an existing ordinary session's Agent; there is no draft-phase model choice to fold into session creation, and subagent continuation deliberately exposes no independent model-selection contract.
- **Directory names are presentation-only** — selection and persistence use provider/model/effort ids; a provider whose catalog or exact-model metadata lookup fails lists as an unselectable failure row until reload.
- **No arbitrary effort input** — the composer offers only the exact model's adapter-advertised levels; an adapter without reasoning metadata leaves the Effort row absent.
